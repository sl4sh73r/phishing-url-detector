## Слайд 1. Титул
- Название: «Детектор фишинговых URL на Java + Weka»
- Автор: Мысливец Л. В., БСМО-12-25
- Дисциплина: Машинное обучение, 2026
- *Говорим:* «Здравствуйте, представлю проект...»

## Слайд 2. Актуальность
- Фишинг — топ-3 вектор атак (IBM X-Force 2025)
- В РФ: 50%+ инцидентов начинаются с фишинговой ссылки
- Антифишинг-системы (Safe Browsing, PhishTank) — обязательный слой защиты
- *Картинка:* статистика фишинговых атак

## Слайд 3. Постановка задачи
- Дано: URL и его метаданные
- Нужно: классифицировать → фишинг (-1) / легитимный (1)
- Метрики: Accuracy, Precision, Recall, F1, ROC AUC

## Слайд 4. Датасет
- UCI Phishing Websites (2015)
- 11 055 записей × 30 признаков
- Баланс классов 56/44
- Примеры признаков: длина URL, наличие IP в домене, SSL state, age of domain, ...

## Слайд 5. Стек технологий
- Java 17 + Maven 3.9
- Weka 3.8.6 (Random Forest, Logistic, J48)
- SLF4J + JUnit 5
- Сборка: `mvn package` → fat jar
- *Аргумент для Ксенофонтова:* «Java + Weka — production-grade стек, не как Python-ноутбук»

## Слайд 6. Архитектура проекта
- Структура: App → DataLoader → ModelTrainer → ModelEvaluator → Reporter
- Простая SRP-разбивка
- Каждый компонент тестируем
- *Картинка:* блок-схема

## Слайд 7. Модели
- **Random Forest** — 100 деревьев
- **Logistic Regression** — L2-регуляризация
- **J48** — Java C4.5 с pruning
- 10-fold stratified CV, seed = 42

## Подсказки на защите

- На вопрос «почему не XGBoost / нейросети?» — «классические методы — baseline; XGBoost есть в плане развития (слайд 11)».
- На вопрос «почему 10-fold, а не train/test split?» — «фиксирует variance оценки, рекомендуется при объёме < 100k».
- На вопрос «как выбирали гиперпараметры?» — «стандартные пресеты Weka; grid search — дальнейшая работа».
- На вопрос «можно ли применять в проде?» — «как baseline detector — да, но в production обычно гибрид (правила + ML + threat intel)».
