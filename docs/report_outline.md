## 1. Введение

Фишинг остаётся одной из ведущих угроз кибербезопасности: по данным IBM X-Force 2025 он входит в топ-3 векторов проникновения, а в отчёте ENISA Threat Landscape — на первом месте по охвату пользователей. Автоматическая фильтрация подозрительных URL — обязательный компонент антифишинговых решений (Google Safe Browsing, PhishTank, корпоративные secure web gateways).

Данная работа исследует применение трёх классических алгоритмов машинного обучения для детекции фишинговых URL на табличных признаках. Реализация выполнена на языке Java с использованием библиотеки Weka 3.8.6.

## 2. Постановка задачи

**Задача:** бинарная классификация URL — фишинговый (`-1`) или легитимный (`1`).

**Цель проекта:**
- сравнить три алгоритма ML на одном датасете;
- выявить признаки, дающие наибольший вклад в детекцию;
- оценить применимость классических методов для задачи.

**Метрики качества:** Accuracy, Precision, Recall, F1, ROC AUC.

## 3. Описание датасета

UCI «Phishing Websites» (Mohammad, Thabtah, McCluskey, 2015):

- 11 055 записей;
- 30 признаков (длина URL, наличие IP, SSL state, HTTPS token, длительность регистрации домена, ...);
- бинарный таргет `Result`.

Распределение классов: легитимных — 6 157, фишинговых — 4 898 (баланс ~56/44).

## 4. Методология

### 4.1 Используемые модели

1. **Random Forest** — ансамбль решающих деревьев. 100 деревьев, bagging + random subspace.
2. **Logistic Regression** — линейная модель с сигмоидой и L2-регуляризацией (реализация Weka `Logistic`).
3. **J48 Decision Tree** — Java-реализация C4.5 с pessimistic pruning.

### 4.2 Схема оценки

10-fold stratified cross-validation, random seed = 42. Метрики усредняются по фолдам (weighted average по классам — формат, который выдаёт `weka.classifiers.Evaluation`).

### 4.3 Стек

- Java 17, Maven 3.9.
- Weka 3.8.6 (core).
- SLF4J 2.0, JUnit 5.

## 5. Результаты

| Модель | Accuracy | Precision | Recall | F1 | ROC AUC | Время CV |
|---|---|---|---|---|---|---|
| **Random Forest** | **0.972** | **0.972** | **0.972** | **0.972** | **0.996** | 1.16 с |
| J48 | 0.958 | 0.958 | 0.958 | 0.958 | 0.985 | 0.23 с |
| Logistic Regression | 0.940 | 0.940 | 0.940 | 0.940 | 0.987 | 1.31 с |

*Прогон от 2026-05-13, seed = 42, 10-fold stratified CV.*

### Confusion matrices

**Random Forest:**

|  | classified as -1 | classified as 1 |
|---|---|---|
| actual -1 (phishing) | 4705 | 193 |
| actual 1 (legitimate) | 119 | 6038 |

**J48:**

|  | classified as -1 | classified as 1 |
|---|---|---|
| actual -1 (phishing) | 4611 | 287 |
| actual 1 (legitimate) | 177 | 5980 |

**Logistic Regression:**

|  | classified as -1 | classified as 1 |
|---|---|---|
| actual -1 (phishing) | 4525 | 373 |
| actual 1 (legitimate) | 287 | 5870 |

**Обсуждение.** Лучший результат ожидаемо показывает Random Forest за счёт ансамблевого подхода и устойчивости к корреляциям признаков (Accuracy 0.972, ROC AUC 0.996 — практически идеальное ранжирование). J48 уступает RF всего на 1.4 п.п. accuracy и при этом обучается в 5 раз быстрее, поэтому для production-сценариев с ограничением по latency может быть предпочтителен. Logistic Regression стабильно слабее (0.940) — линейная модель не улавливает нелинейные взаимодействия между признаками, но даёт хороший интерпретируемый baseline.

Все три модели делают **больше ошибок второго рода (FN — пропуск фишинга)**, чем первого. Например, у RF: 193 фишинговых URL ошибочно классифицированы как легитимные против 119 наоборот. Это критично для практики антифишинга — стоит рассмотреть class weighting или calibration threshold для смещения операционной точки в сторону recall на класс «-1».

## 6. Анализ важности признаков

Топ-10 признаков по Information Gain:

| # | Признак | IG |
|---|---|---:|
| 1 | `SSLfinal_State` | 0.499 |
| 2 | `URL_of_Anchor` | 0.477 |
| 3 | `Prefix_Suffix` | 0.123 |
| 4 | `web_traffic` | 0.115 |
| 5 | `having_Sub_Domain` | 0.110 |
| 6 | `Links_in_tags` | 0.047 |
| 7 | `Request_URL` | 0.047 |
| 8 | `SFH` | 0.037 |
| 9 | `Domain_registeration_length` | 0.037 |
| 10 | `Google_Index` | 0.012 |

**Интерпретация.** Два признака — `SSLfinal_State` (валидность TLS-сертификата) и `URL_of_Anchor` (доля внешних якорей) — дают суммарный Information Gain ≈ 0.98, что и объясняет высокое качество моделей. Это согласуется с практикой:

1. Фишинговые сайты массово используют свеже-выпущенные Let's Encrypt-сертификаты или вообще обходятся без HTTPS — фича `SSLfinal_State` хорошо детектит обе ситуации.
2. Якорные ссылки на фишинговых страницах часто ведут на сторонние домены (или используют `#`, `javascript:void(0)`) для маскировки кражи учётных данных.
3. `Prefix_Suffix` (дефис в домене типа `paypal-secure.com`) — классический индикатор typosquatting.
4. Признаки реализуемые «без сети» (длина URL, наличие IP) попали в нижнюю часть рейтинга — это сигнал, что простой regex-фильтр URL малоэффективен против современного фишинга.

## 7. Выводы

1. Все три классических ML-алгоритма (Random Forest, Logistic Regression, J48) применимы для детекции фишинговых URL по табличным признакам со средневзвешенной F1 ≥ 0.94.
2. Лучшая модель — **Random Forest**: Accuracy = 0.972, F1 = 0.972, ROC AUC = 0.996.
3. Главные признаки: SSL-состояние (IG = 0.499), якорные ссылки (IG = 0.477), наличие префикса/суффикса в домене (IG = 0.123).
4. Дальнейшие направления:
   - использование XGBoost / LightGBM как сильных бустингов;
   - расширение признакового пространства (lexical, host-based, content-based);
   - онлайн-обучение на свежих PhishTank-данных;
   - объединение с правилоами на основе deny-list.
